# 快捷键页面重构：IDEA 风格紧凑表格布局

## 背景与目标

当前快捷键设置页面使用大卡片网格布局（每张卡片最小高度 136px），35 个快捷键分 8 个类别。随着快捷键数量增长，页面过长，用户难以快速找到和定位特定快捷键。

**目标**：将快捷键页面重构为 IntelliJ IDEA Keymap 风格的紧凑表格布局，提供搜索过滤、分类折叠、内联编辑能力，大幅提升可用性和信息密度。

## 用户与使用场景

- **主要用户**：需要查看或修改快捷键配置的应用用户
- **核心场景**：
  1. 查找某个功能的快捷键是什么
  2. 修改某个快捷键绑定
  3. 查看是否有快捷键冲突
  4. 恢复某个快捷键为默认值

## 功能需求

### F1: 紧凑表格布局

将当前的卡片网格替换为单列紧凑表格/列表布局：

- **每行一个快捷键**，水平排列：图标 + 操作名称 + 快捷键输入框 + 默认值 + 恢复默认按钮
- 类别作为**可折叠分组头**，显示类别名称和子项数量（如 "App · 3 items"）
- 默认全部展开；折叠状态仅在会话内保持（不持久化）
- 响应式：窗口变窄时隐藏默认值列或缩短操作名截断，而非降列

### F2: 搜索与过滤

在页面顶部提供搜索栏：

- **名称搜索**：输入关键词，实时过滤匹配操作名称的快捷键（模糊匹配，不区分大小写）
- **按键搜索**：输入按键组合（如 `Cmd+S`），过滤绑定了该组合的快捷键，用于发现冲突
- 两种搜索模式通过同一搜索框自动识别——输入纯文本走名称匹配，输入含修饰键的组合走按键匹配
- 搜索时自动展开包含匹配项的类别，折叠无匹配项的类别
- 无匹配时显示空状态提示

### F3: 内联编辑快捷键

保持现有的按键录入交互（点击输入框 → 按下新组合 → 自动保存），但优化体验：

- 输入框获得焦点时显示高亮边框，提示用户可以按键录入
- 录入成功后短暂闪烁确认动画
- 支持 Backspace/Delete 清除快捷键
- 检测冲突：如果录入的组合已被其他快捷键使用，在该行下方显示冲突提示（指向冲突项）

### F4: 视觉设计

- 保持当前项目的整体设计语言（圆角、颜色变量、字体等）
- 类别分组头使用 subtle 背景区分
- 行 hover 高亮
- 图标保留（使用现有的 `shortcutIconByActionId` 映射），但尺寸缩小以适应紧凑行高
- 快捷键输入框居中显示格式化的按键符号（使用现有 `formatShortcutForPlatform`）

## 非功能需求

- **可访问性**：搜索框和快捷键输入框保持 aria-label；折叠类别支持键盘操作
- **性能**：35 个快捷键无性能压力，但搜索过滤应避免不必要的重渲染
- **兼容性**：复用现有的 `shortcutDrafts`、`updateShortcut`、`handleShortcutKeyDown` 逻辑，不改变底层数据模型

## 不在范围内

- 不改变快捷键的存储方式或 `AppSettings` 类型
- 不新增快捷键类别或操作
- 不做拖拽排序
- 不做快捷键导入/导出
- 不改变快捷键的分发逻辑（`keyboardDispatcher` 等）

## 成功标准

- 一屏可显示全部 35 个快捷键（或绝大部分），无需大幅滚动
- 用户可以通过搜索在 2 秒内定位到目标快捷键
- 编辑快捷键的操作步数不超过当前版本
- 视觉上保持与项目整体 UI 风格一致
