# 输出区域精致度提升 — 需求文档

---

## Summary

将对话输出区从"功能可用"提升到"视觉精致"。分两阶段推进：先通过 CSS 微调快速提升基线质感，再引入时间轴流式布局重构信息结构，最终实现层次清晰、噪音低、空间紧凑的输出体验。

---

## Problem Frame

当前输出区域的核心问题是**视觉层级缺失**。所有工具调用以相同权重渲染——卡片边框、绿色状态点、行内文字均匀堆叠——连续操作时屏幕变成一面"卡片墙"，没有主次之分。具体表现为：

1. **折叠态工具卡片** `border-color: transparent`，几乎没有容器感，"浮"在背景上
2. **绿色状态点**在每个工具行重复出现，产生视觉噪音
3. **搜索结果**像原始日志平铺，文件名和匹配行无层级区分
4. **消息与工具之间间距统一**，缺乏语义分层的节奏感
5. **思考区块**仅靠 1px 左边框区分，展开后视觉分离度不够
6. **边界分隔线**权重低，快速滚动时容易被忽略

用户期望从"能用"达到"精致"，参考对标：Linear 工具卡片、Raycast 搜索结果、Arc 边界分隔线。

---

## Key Decisions

1. **两阶段渐进而非一步到位** — Phase 1 做 CSS 微调拉到 75 分，Phase 2 做时间轴重构冲 90 分。原因：降低风险，Phase 1 可独立交付并验证方向。

2. **时间轴默认折叠已完成操作** — 已完成的工具调用默认只显示一行摘要，点击展开查看详情。处理中的操作保持展开。牺牲信息即时可见性，换取更干净的扫读体验。

3. **时间轴竖线始终可见** — 即使所有操作都已完成，竖线也不消失，提供一致的视觉锚点。

4. **搜索结果结构化在两个阶段复用** — Phase 1 的搜索结果 CSS（B1-B3）在 Phase 2 时间轴中同样适用，不会重复劳动。

---

## Requirements

### Phase 1: CSS 视觉基线提升

#### 工具卡片微增强

R1. 折叠态 `.task-container` 需要轻微底色，使用 `color-mix()` 与消息背景混合，让折叠行有若隐若现的容器感，而非完全透明。

R2. 展开态 `.task-container` 需要微妙阴影（`box-shadow`）和柔和边框，与背景形成视觉分离。

R3. 状态指示器简化：Phase 1 中将绿色圆点替换为工具图标本身的颜色状态（成功=绿色，失败=红色，处理中=黄色），减少重复的绿点噪音。Phase 2 时间轴会进一步用节点状态替代。

#### 边界分隔线增强

R4. 转场边界 `.messages-turn-boundary` 增加上下间距（从 `14px 0 10px` 增至 `20px 0 16px`），并在快速滚动时更易识别。

R5. 分隔线渐变端点提高不透明度，标签字距从 `0.03em` 增至 `0.06em`。

#### 思考区块增强

R6. 思考区块 `.thinking-block` 展开态增加轻微背景色和圆角，与周围内容视觉分离。

R7. 思考区块左侧 border 从 1px 增至 2px，处理中状态（`.is-live`）使用主题色高亮。

#### 搜索结果结构化

R8. 搜索结果中文件名行加粗并添加浅色背景，建立明确的视觉锚点。

R9. 匹配行添加左侧 accent border + 缩进，与文件名行形成层级关系。匹配关键词用 `mark` 高亮。

R10. 空搜索结果（"No matches found"）使用更小字号、斜体、淡色，视觉降权。

#### 消息节奏优化

R11. 工具区块与下一个非工具消息之间的间距大于工具区块之间的间距，形成语义分层。

---

### Phase 2: 时间轴流式布局

#### 时间轴结构

R12. 输出区域引入竖线（timeline line）+ 节点（node）串联所有工具操作，替代当前独立卡片堆叠。竖线始终可见，不随操作完成而消失。

R13. 每个操作节点由：节点圆点 + 摘要行（图标 + 操作名 + 简要信息）组成。节点圆点反映操作状态（完成/处理中/失败）。

R14. 处理中的操作节点使用脉动动画高亮，视觉上明确当前焦点。

#### 折叠/展开交互

R15. 已完成的操作默认折叠为单行摘要。点击摘要行可展开查看完整详情（文件列表、搜索结果、命令输出等）。

R16. 处理中的操作默认展开，完成时自动折叠为摘要行。

R17. 展开后的详情复用现有的工具块渲染（ReadToolGroupBlock、SearchToolGroupBlock 等），不改变展开内容的渲染逻辑。

#### 空间紧凑化

R18. 相同类别的连续操作（如连续读文件）在时间轴中视觉归组，通过缩进或背景色区分组边界，替代当前的独立卡片堆叠。

R19. 操作间的纵向间距从当前 `8px` 收紧至 `4px`，通过时间轴竖线提供视觉连续性补偿。

---

## Scope Boundaries

- **不改底层分组逻辑** — `groupToolItems` 的分类和合并规则保持不变
- **不改数据模型** — `ConversationItem` 类型和 `ToolItem` 结构不动
- **不改展开后的渲染** — markdown 渲染、diff 视图、命令输出等展开内容的渲染逻辑不变
- **不新增工具块类型** — 不为时间轴引入新的 ToolBlock 变体
- **助手消息底色（E2）暂不纳入** — 影响面大，需独立验证，后续可单独评估
- **虚拟化逻辑不变** — `@tanstack/react-virtual` 的虚拟滚动机制保持现有实现

---

## Success Criteria

1. **视觉层级** — 输出区域有明确的三级层次：时间轴结构 > 操作摘要 > 展开详情
2. **噪音降低** — 绿色状态点不再在每个工具行重复出现
3. **空间效率** — 同等操作数量下，输出区域纵向占用减少 30% 以上
4. **扫读体验** — 用户可以快速扫过操作时间轴，只在需要时展开详情
5. **主题兼容** — 所有改动在深色/浅色主题下均表现一致
6. **无障碍** — `prefers-reduced-motion` 下禁用脉动动画

---

## Dependencies / Assumptions

- 依赖现有的 CSS 变量体系（`--surface-card`、`--border-subtle`、`--color-success` 等）
- 依赖 `color-mix()` CSS 函数在目标平台（Tauri WebView）的兼容性
- Phase 2 时间轴组件需要与现有的虚拟化层（`buildTimelineProjectionRows`）协作
- 现有组件中较多的 inline style（如 `ReadToolGroupBlock` 的 `style={{}}`）在 Phase 2 中需清理到 CSS class
